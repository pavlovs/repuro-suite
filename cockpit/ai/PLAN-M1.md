## Locked decisions
- **Location:** `CLAUDE_REPURO/cockpit/` (this folder). DB at `data/cockpit.db`, `journal_mode=DELETE`, never committed.
- **Stack:** Python 3.12, FastAPI + uvicorn, stdlib `sqlite3` (no ORM), pytest + httpx for tests, openpyxl (read-only) for seed import. venv at `.venv/`. Port **8099**.
- **Principals (M1):** `rd` (human), `rc-agent` (agent). Tokens: 32-byte urlsafe random, stored sha256-hashed in `users.token_hash`, generated by `python cockpit.py token <principal>` which prints the token once and writes the hash. Plaintext tokens live only in the caller's `.env`/skill config — never in the DB or git. FF/fc-agent added at M5.
- **Auth:** `Authorization: Bearer <token>` on every `/api/*` route except `/api/health`. 401 without, 403 for scope violations (agent tokens cannot approve results — reviewer actions require a human principal).
- **Schema:** exactly DESIGN-SPEC §4.1 (users, deal_mirror, workstreams, deliverables, tasks, audit_log). `tasks.prereqs` JSON: `[{"ref": "t-<id>" | "d-<id>", "hardness": "hard"|"soft"}]`. IDs: `t-` prefix tasks, `d-` deliverables, `w-` workstreams, integer autoincrement behind the prefix.
- **Computed logic (pure functions in `src/compute.py`, no DB access):**
  - Readiness (§4.2): green = no prereqs or all hard prereqs done; amber = any hard prereq in_progress OR any soft prereq not done(*); red = any hard prereq open/blocked/waiting. (*)soft prereq done/in_progress → does not block green only if all hard prereqs done and no soft prereq is open/blocked — i.e. green requires hard all-done AND soft none-open; amber otherwise unless red.
  - Schedule risk: `overdue` (deadline < today), `at_risk` (deadline ≤ today+7 AND readiness ≠ green), `chase` (status=waiting AND next_chase_date ≤ today). Multiple can apply; report as list.
  - Recommendation (§4.3): `today` = overdue OR deadline ≤ tomorrow OR pinned_today OR chase-due; `this_week` = deadline ≤ today+7 OR prereq-of-task-due-≤14d OR expected_back_by ≤ today+7; else `later`. Status=waiting items NEVER `today`/`this_week` via their own deadline — only via chase/expected_back dates.
  - Effective deadline = task.deadline or parent deliverable.target_date or null.
  - Deliverable roll-up: worst readiness among its open tasks; overdue target_date → forces `overdue` risk on the deliverable.
  - Staging exclusion: tasks/deliverables with `staging=1` are excluded from readiness inputs, recommendations, and the future Blockers panel data.
- **deal_mirror sync (`src/dealroom_sync.py`):** source `<workspace>/dealroom/data/dealroom.db` opened with `file:...?mode=ro` URI (LEARNINGS rule — never plain connect). Reads `SELECT code_name, deal_stage, status_note FROM deals`. Upserts deal_mirror (codename pk, stage, note=status_note, synced_at=now). Runs at app startup + every 300s (asyncio task) + on `POST /api/sync/dealroom`. Source path configurable via `COCKPIT_DEALROOM_DB` env var (tests point it at a fixture). Sync failure (file locked/missing) → log + keep stale mirror + surface `synced_at` age in `/api/state.meta`; never crash the app.
- **Mutations:** all writes carry `version` (int). Mismatch → 409 with current entity. Every mutation writes audit_log (actor from token, action, entity, before/after JSON). DB writes serialized through one connection with a lock (single-process app; same pattern as cockpit M1 bridge).
- **Agent queue:** claim sets `claimed_by` + `claim_expires_at = now + 4h`; heartbeat extends by 4h; expired claims auto-revert to open on any queue read (lazy reaping — no background job needed in M1). `result` requires `idempotency_key`; replay with same key returns the original 200 without re-applying. Result → status `in_review` always (agent_auto deferred to v1.1 — even if a task says agent_auto, M1 routes to in_review). Approve/reject endpoints require human principal.
- **MD export (`GET /api/export.md?scope=`):** scopes `all` (human only), `person:RD`, `workstream:<id>`, `deal:<codename>`, `agent-queue`. Format: deterministic markdown — workstream H2, deliverable H3, task lines `- [ ] t-041 | <text> | deadline | responsible | status | readiness | risk | prereqs`. Agent tokens: all scopes except `all`.
- **MD import (`POST /api/import`, body = MD text, `?dry_run=true` default false):** accepts ONLY the §6.2 format: `## task-update` (requires `id:`) and `## new-task` blocks. No `deal-status` block (stage comes from mirror only). Unknown keys/enums/IDs or ambiguous deliverable names → reject the entire request with line-level errors (fail closed, all-or-nothing — partial application would corrupt audit trail). dry_run returns the would-be diff as JSON.
- **Seed import (`scripts/seed_workplan.py`):** reads `<onedrive>/General/01_Workplan/260312_Repuro_Workplan_v1.xlsx` sheet `Workplan` via openpyxl read-only. Maps: Workstream→workstreams (4 expected: Fundraising, Octopus, Pipeline, Admin), Deliverable→deliverables, Activity rows→tasks (kind=workplan, staging=1, responsible/priority/deadline/comment as-is; rows with empty Activity skipped). Responsible mapping: literal strings preserved in `responsible` (e.g. "FF, RD; External Legal") — no parsing into principals in M1. Idempotent: re-run wipes and re-inserts only `staging=1` rows created by source tag `seed-v1`.
- **No UI, no skills, no Fly, no CMA, no TASKS.md integration in M1.**
- **FC code ownership rule applies** (workspace CLAUDE.md): RC implements all M1 code.
