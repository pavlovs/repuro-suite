block — core workflow and security gaps make this unsafe for investor-facing use without fixes.

## Critical issues
1. `src/templates/dashboard.html:763`, one-pager edits are saved as `innerHTML` while rendering expects plain bullet text (`bulletHtml` at `:577-585`), so reloading turns edited content into escaped HTML-like garbage instead of clean bullets; save `innerText`/normalized lines and render from a canonical text format.
2. `src/db.py:858` (and migration chain at `:1212-1215`), DR-M9 one-pager columns are not added in DB migrations, but generator and deal view read them directly (`src/generate/onepager.py:239-241`, `src/dashboard.py:488-497`); add one-pager columns to schema migration (idempotent `_add_col`) so `draft-onepager` works on fresh DBs.
3. `src/templates/dashboard.html:382` and `:449-450`, portfolio text fields (`description`, `status_text`) are injected as raw HTML, enabling stored XSS via contenteditable/API updates; HTML-escape all user/DB text before `innerHTML` insertion (or render via text nodes).
4. `src/templates/dashboard.html:706-712`, current trading card renders only for LTM and hides YTD-only data, causing false “no current trading” output; render when either LTM or YTD exists and label period explicitly.

## Secondary issues
1. `src/templates/dashboard.html:684-702`, Q2 omits the specified EBITDA-margin line overlay, reducing interpretability for investor discussions; add margin series overlay (or explicit fallback note when insufficient points).
2. `src/templates/dashboard.html:749` with `src/templates/dashboard.html:595-644`, save indicator logic targets `.op-save-ind` but that element is never rendered, so users get no one-pager save confirmation; add indicator element in header and keep it updated on save.
3. `src/dashboard.py:1079`, `/api/update` parses JSON without error handling and can throw on malformed payloads; use guarded parsing (like `_read_json_body`) and return `400` on invalid JSON.
4. `src/generate/onepager.py:238-249`, re-generation guard is global (`onepager_edited_at > onepager_generated_at`) and blocks all quadrants, even when regenerating a different untouched quadrant; track/edit timestamps per quadrant or guard per requested quadrant.

- **Missing**: GP-level questions not well covered yet include customer concentration evidence, customer segment mix, order backlog/Auftragsbestand visibility, and hard next blocker ownership/date.
