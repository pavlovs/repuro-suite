## Verdict
block — commercially unsafe as written because it can put unverified, audience-misaligned investor copy on screen from invented or underspecified data sources.

## Critical issues
1. `ai/SPEC-INVESTOR-COCKPIT.md:98-107,151-160,174-183,304-306` — Q1/Q3/Q4 are investor-facing narrative bullets, but the spec only optimizes for style and editability, not factual approval. That is too weak for claims like seller motivation, competitive position, recommendation, blockers, and customer concentration. Suggested fix: add a hard publish gate before investor use, require source-backed evidence per bullet, and force unsupported claims to render as omitted/TBD rather than inferred prose.
2. `ai/SPEC-INVESTOR-COCKPIT.md:67-77,144-162` — Q3 mixes internal deal-control content with investor-facing presentation: open actions, blockers, valuation range, implied multiple, and deal-structure split. That is poor audience fit for external investor meetings and can leak negotiation posture or unfinished thinking. Suggested fix: split the cockpit into `internal` and `investor` modes, or rewrite Q3 for investor mode to show only stage, target timeline, next milestone, and sanitized headline risks.
3. `ai/SPEC-INVESTOR-COCKPIT.md:115-119,147-149,168-172,257-263` — several facts are presented as if already real, but they are not verifiable in the current system: `deal_actions` uses `priority`, not `importance`; `deal_valuations` does not store an `implied multiple` field; `deals.deal_structure_json` is not defined; `deal_commercial` is not a typed `service_lines/customer segments` object; `draft-onepager` and the `onepager_*` fields are still hypothetical. Suggested fix: replace pseudo-schema with exact existing fields, and label every new dependency explicitly as an upstream schema/API change.
4. `ai/SPEC-INVESTOR-COCKPIT.md:36-43,293-294` — the stage filter hard-codes “All Active” as `valuation + offer + LOI + DD`, which conflicts with the live stage taxonomy where `nda_exchange` is also an active funnel stage. For investor pipeline discussions this can hide real active deals and distort portfolio framing. Suggested fix: define a strict UI-label-to-DB-enum map, decide explicitly whether `nda_exchange` is included or excluded for investor meetings, and state that rationale in the spec.

## Secondary issues
1. `ai/SPEC-INVESTOR-COCKPIT.md:53-65,79,123-136` — the cockpit shows financials and valuation but never requires an “as of” date, latest period label, or freshness marker. A sharp investor will immediately ask whether EV, EBITDA, and current trading are based on FY2024A, 2025P, LTM, or stale numbers. Suggested fix: make the footnote mandatory and include valuation date, latest financial period, and data-completeness status.
2. `ai/SPEC-INVESTOR-COCKPIT.md:123-134` — Q2 hard-codes a 2022-2025P chart shape and KPI row without defining fallback rules for deals that only have 1-2 annual years, no projection year, or mixed annual/YTD coverage. That leaves commercial comparability underspecified. Suggested fix: make the year window data-driven and define exact labeling/fallback behavior for partial histories and forecast-free deals.
3. `ai/SPEC-INVESTOR-COCKPIT.md:49,98-105,151-158,174-181,193-204` — the spec notices German-vs-English variation in the golden corpus but never chooses a required output language for this cockpit. That risks mixed-language investor output and inconsistent German phrasing. Suggested fix: pin one language per audience/mode and validate generated text against that rule.
